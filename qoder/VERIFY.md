# 验证样例

一份可以照着做、结果可预期的最小验证路径。全程约 3 分钟。
环境准备见 [`README.md`](README.md) 第三、四节。

> 所有命令都在 `qoder/` 目录下执行。Windows 用 `.venv\Scripts\python.exe`，
> macOS/Linux 换成 `.venv/bin/python`。

---

## 样例 A：混合检索能不能「按意思」找到出处

**初始数据**：`data/samples/` 下 3 篇笔记，共 15 个知识块
（数据库系统 5 块 / 操作系统 5 块 / 机器学习 5 块）。

**输入**：`为什么 B+ 树插入会变慢`

**操作步骤**

1. 浏览器打开 <http://127.0.0.1:8080>
2. 「混合检索」页输入框粘贴上面的问题，科目选「全部科目」，点「检索」
3. 展开结果列表下方的「查看实际执行的两条 seekdb SQL」

**预期结果**

| 排名 | 主题 | 向量排名 | 全文排名 |
| --- | --- | --- | --- |
| 1 | B+ 树索引的结构 | 1 | 1 |
| 2 | 页分裂为什么会拖慢写入 | 2 | 未命中 |

页面顶部的记忆提示条会显示 PowerContext 是否召回了记忆。

**指定技术在这里起了什么作用**

- **seekdb 向量检索**：问题里没有出现「页分裂」三个字，但语义相近的段落被召回（向量排名 2）。
  如果只做全文检索，这一块会被完全漏掉 —— 因为它不含「变慢」二字，原文写的是「拖慢」。
- **seekdb 全文检索**：把「B+ 树」这个精确术语命中的章节排到第一。
- **RRF 融合**：两条召回列表各自排序后融合，取长补短。
- 页面展示的 SQL 是程序真实执行的语句（向量部分因为 512 维太长，做了 160 字符截断）。

**命令行等价验证**

```bash
.venv\Scripts\python.exe scripts\verify.py
```

输出里的「3. 混合检索 Top3」一节会打印同样的排名和实际 SQL。

## 样例 B：记忆能不能改变下一次的行为

这是本题「技术结合」的核心，必须看到**同一个人、同一个查询，行为因为记忆而不同**。

**初始数据**：样例 A 的 15 个知识块，PowerContext 已启动且为空 Scope。

**步骤 1 —— 写入偏好**

1. 打开「学习档案」页
2. 「设置学习偏好」里填：优先复习科目 = `数据库系统`，每日卡片上限 = `6`
3. 点「写入记忆」

预期：下方出现 `已写入 PowerContext：学习偏好：优先复习科目=数据库系统；每日卡片上限=6`；
「PowerContext 记忆原文」区域刷新后能看到这条记忆（`POST /v1/context/prepare` 的真实返回）。

**步骤 2 —— 验证偏好被复用**

1. 切到「复习教练」页

预期：副标题显示 `共 5 张卡 · 上限 6 · 优先科目 数据库系统 · 参数来自 PowerContext 记忆`；
卡片全部来自「数据库系统」（因为库里正好只有 5 块，上限 6 没有触发截断，
把上限改成 3 再点「重新排队」就能看到截断生效）。

**步骤 3 —— 制造一个薄弱点**

1. 在卡片上点「显示答案」，再点「还不熟」

预期：右侧「薄弱主题（seekdb 聚合）」立即出现该主题，计数 `1/1`；
同时写入了一条记忆 `薄弱主题：xxx`（回到「学习档案」页可见）。

**步骤 4 —— 看到记忆影响检索排序**

1. 回到「混合检索」，搜 `插入新记录会发生什么`
2. 看结果卡片下方的标签

预期：命中该薄弱主题的结果上出现橙色标签 `记忆薄弱点 xxx`，
且 `RRF 得分` 比没有该标签时高 0.008（对应 `RECALL_WEAK_TOPIC_BOOST`）。

**命令行等价验证**

```bash
.venv\Scripts\python.exe scripts\verify.py
```

输出里的「5. PowerContext 写入 -> 召回 -> 影响行为」一节会打印：

```
召回状态: ready
召回内容: ..."学习偏好：优先复习科目=数据库系统；每日卡片上限=6"...
解析出的指令: {"preferred_course": "数据库系统", "card_limit": 6, "weak_topics": [...]}
复习队列长度（受记忆里的上限影响）: 6
```

**指定技术在这里起了什么作用**

- PowerContext 不是「装了个组件」：`prepare` 返回的文本被解析成
  `preferred_course` / `card_limit` / `weak_topics` 三个参数，分别改变了
  **检索排序权重**、**复习队列长度**、**薄弱主题加权**。
- 写记忆之前会先读一次，同一薄弱点不重复写 —— 这是 `coach.grade()` 里的逻辑，
  可以在「学习档案」页看到记忆条目不会随反复点击而无限增长。

## 样例 C：新增资料能不能立刻被检索到

**输入**：在「资料库」页粘贴一段新内容

```
标题：编译原理-语法分析
科目：编译原理
正文：
## LL(1) 文法的判定条件
一个文法能使用 LL(1) 分析的前提是：对每个非终结符，其各候选式的 FIRST 集两两不相交；
若某候选式能推出空串，则 FIRST 集与 FOLLOW 集也不能相交。满足这两条就能做无回溯的自顶向下分析。

## 递归下降与预测分析表
递归下降给每个非终结符写一个函数，靠向前看一个 token 决定走哪条分支。
预测分析表把选择逻辑做成二维表 M[非终结符, 终结符]，用显式栈代替递归，避免深递归爆栈。
```

**操作步骤**

1. 「资料库」页填好标题/科目/正文，点「导入到 seekdb」
2. 切到「混合检索」，搜 `什么时候可以用自顶向下分析`

**预期结果**

- 导入提示 `已写入 2 个知识块`，右上角计数变成 `17 块 / 4 篇`
- 检索第一条命中「LL(1) 文法的判定条件」，出处显示 `inline/编译原理-语法分析`
- 若刚导入就搜、向量索引还没追平，SQL 展示区会多出一条注释
  `-- 向量索引为异步构建，索引尚未追平时用精确扫描补足 N 行`，结果依然正确

## 一键复现全部验证

```bash
# 重置到干净状态（删掉复习记录，保留资料）
.venv\Scripts\python.exe -c "import sys;sys.path.insert(0,'.');from app.store import SeekDB;SeekDB.instance()._query('DELETE FROM review_log')"

# 跑验证，并把结果导出成 JSON 附在提交材料里
.venv\Scripts\python.exe scripts\verify.py --json verify_report.json
```

期望最后一行：`结果：6 步，失败 0，跳过 1`（跳过的是「导入示例资料」，
因为库里已有数据；从空库跑就是 `失败 0，跳过 0`）。
