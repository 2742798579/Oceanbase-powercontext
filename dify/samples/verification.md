# 验证样例

一组可以照着走完的完整样例。**在 Dify 应用里操作**见 A 部分，**不开 Dify 直接验证后端与 seekdb** 见 B 部分。

对应运行证据：`docs/evidence/verify-20261028-225805.log`。

> 说明：玩家标识固定为 `verify-demo`，因此花名、次数、余额可复现；当票号含随机后缀，每次不同。

---

## 初始状态

```bash
cd dify/backend
python seed.py --reset      # 清空并重建，写入 10 条预置旧账
python -m uvicorn app:app --host 0.0.0.0 --port 8077
```

- `lies` 集合：10 条预置旧账（SEED-001 ~ SEED-010，来自 `data/seed_lies.json`）
- `players` 集合：空
- 嵌入模式：本文档记录的结果使用 `EMBEDDING_PROVIDER=hash`（离线降级，无语义能力）。配好真实嵌入模型后语义相似度更准，但流程与判定逻辑完全一致。

---

## A. 在 Dify 里体验（主路径）

导入 `dsl/lie-pawnshop.chatflow.yml`、绑好模型、确认 `BACKEND_BASE` 后，在应用「运行」面板里按顺序输入。

### A1. 当掉一句原创谎言

**输入**
```
我奶奶那把蒲扇一扇，整条巷子的暑气就退了三里地
```

**预期**
- 走「典当」分支（不含"查账"/"赎回"关键词）
- 老板说一段话，像做惯生意的当铺掌柜，120 字以内
- 下方出现当票：当票号、估价、判定「照价入库」、账上余额
- 估价约 200 文上下（篇幅 + 亲历口吻加分）

**实际结果**
```
当票号：D-20261028-57B5C5
估价：221 文　判定：照价入库
熟客档案：吴穿木屐货郎，第 1 次，被识破 0 次，账上 221 文
老板态度：头回见——把来客当肥羊打量，客气里带试探
```

### A2. 当一句和旧账几乎一样的

**输入**
```
我敲更的时候把月亮敲下来过，后来自己搬梯子挂回去了
```

**预期**
- 触发**撞当**：判定变成「撞当·折价入库」，价格打七折
- 当票里点名撞上了谁（赵缺牙更夫）和那句旧话
- 老板的台词里会说破这件事

**实际结果**
```
当票号：D-20261028-A14BFE　估价：124 文　判定：撞当·折价入库
撞当对象：SEED-003「我敲更的时候把月亮敲下来过，后来自己爬梯子挂回去了」
          （赵缺牙更夫，相似度 0.945）
当前账上：345 文，被识破 1 次
```

### A3. 查账

**输入**
```
查账
```

**预期**：列出该玩家的全部当票，按时间倒序，带合计。

**实际结果**
```
**账册 · 吴穿木屐货郎**　共 2 笔，合计 345 文

- `D-20261028-A14BFE`　「我敲更的时候把月亮敲下来过，后来自己搬梯子挂回去了」　124 文　撞当·折价入库
- `D-20261028-57B5C5`　「我奶奶那把蒲扇一扇，整条巷子的暑气就退了三里地」　221 文　照价入库
```

### A4. 按关键词翻整本账册（混合检索）

**输入**
```
查账 月亮
```

**预期**：走 `hybrid_search`，全文命中"月亮"的排在前面，后面是向量近邻。

**实际结果**
```
**账册 · 检索「月亮」**（全文 + 向量混合检索，共 6 条）

- `SEED-003`　「我敲更的时候把月亮敲下来过，后来自己爬梯子挂回去了」　405 文　— 赵缺牙更夫
- `D-20261028-A14BFE`　「我敲更的时候把月亮敲下来过，后来自己搬梯子挂回去了」　124 文　— 吴穿木屐货郎
- `D-20261028-57B5C5`　「我奶奶那把蒲扇一扇，整条巷子的暑气就退了三里地」　221 文　— 吴穿木屐货郎
- `SEED-004`　「我打的这张桌子会自己记账，比账房先生还准」　233 文　— 陈木匠
- `SEED-005`　「我给一条街的井都接过骨，现在它们会互相打招呼」　287 文　— 孙游医
- `SEED-002`　「上个月我在楼下便利店买到了三千年前的月饼」　312 文　— 李青衫书生
```

> 后 4 条是向量近邻召回，属正常现象——混合检索会同时返回字面命中与语义相近的条目。配置真实嵌入模型后，这一段的排序会更有意义。

### A5. 赎回

**输入**
```
赎回
```

**预期**：赎回最近一张当票，扣「原估价 × 1.2」，余额减少。

**实际结果**
```
**赎回 D-20261028-A14BFE**

老板从柜底抽出那张当票，念了一遍：「我敲更的时候把月亮敲下来过，后来自己搬梯子挂回去了」

- 赎金：149 文（原估价 124 文，加两成利）
- 账上余额：196 文
```

### A6. 跨会话记忆（重点）

**操作**：在 Dify 里点「新对话」开一个**全新会话**（`conversation_id` 变了，`sys.user_id` 不变），再输入：

```
我家楼下的煎饼摊其实是我开的，摊主是我雇的
```

**预期**
- 老板开口时先提一句"上次你当的是……"，说明他记得
- 档案里来店次数累加，账上余额延续

**实际结果**（后端喂给模型的 `<memory>` 片段原文）
```
上次他当的是：「我敲更的时候把月亮敲下来过，后来自己搬梯子挂回去了」，124 文。
账册里语义相近的旧账：
  - 「我唱戏的时候，台下的椅子会跟着一起哭」（褚戏子当的，319 文，相似度 0.26）
  - 「我押的这趟镖是给皇帝送一封没写完的信」（郑镖师当的，274 文，相似度 0.26）
  - 「我家的猫会背唐诗三百首，还会挑押韵的背」（王跛脚货郎当的，268 文，相似度 0.22）
```
```
估价：192 文　判定：照价入库　账上：388 文
```

> 这一步是"记忆真的存在库里"的直接证据：新会话里模型拿到的上下文带着上一轮的当票内容，而这段内容只可能来自 `players` 集合。

## B. 不开 Dify，直接验证后端与 seekdb

```bash
# 后端跑起来之后，在 dify/ 目录下
python scripts/verify.py
```

脚本自动跑完 A1–A6 的等价流程，结果写入 `docs/evidence/verify-<时间戳>.log`。

### seekdb 实际读写记录

典当一次（A6 那一步）后端记录的 trace：

```
[get]           players  {"ids": ["verify-demo"], "hit": true}
[query.vector]  lies     {"n_results": 3, "returned": 3, "top": "我唱戏的时候，台下的椅子会跟着一起哭"}
[index.refresh] lies     {}
[add]           lies     {"ids": ["D-20261028-781A5A"], "quote": 192, "verdict": "照价入库"}
[index.refresh] players  {}
[upsert]        players  {"player_id": "verify-demo", "nickname": "吴穿木屐货郎",
                          "visits": 3, "caught": 1, "wealth": 388, "last_lie": "..."}
```

含义：读熟客档案 → 向量检索历史当票 → 写新当票 → 刷新索引 → 更新熟客档案。每一步都真实落库。

## 恢复初始状态

```bash
python seed.py --reset
```

清空 `lies` / `players` 两个集合，重新写入 10 条预置旧账。想换一个"新玩家"，改 `VERIFY_PLAYER` 环境变量，或在 Dify 里换一个用户即可。
